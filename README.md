# AI Workspace — стартовый набор

Рабочее пространство для Claude Code. Забрал — заполнил — работаешь.

Сделано для команд: контекст компании пишет не один человек, а каждый про своё направление.

---

## Как забрать себе

**Не нужен GitHub-аккаунт и не нужен git.** Создайте на своём компьютере пустую папку, откройте её через Claude Code и скажите:

> Сходи в репозиторий https://github.com/miheydev/ai-workspace-ru и скопируй его содержимое сюда.

Он всё принесёт. Тот же приём работает для любых знаний, которые вы найдёте в сети — попросите принести и разложить.

Если git привычнее:

```bash
git clone https://github.com/miheydev/ai-workspace-ru.git
```

---

## Три шага после установки

### 1. Заполните контекст компании

```
/обогатить-компанию
```

Спросит название, сайт и ИНН, дальше уйдёт собирать. Работает долго — запустите и займитесь другим. Вернётся с восемью заполненными разделами и честным списком того, чего не нашёл.

**Дальше руками.** Всё, что не восстанавливается снаружи — как устроены закупки, где теряется сырьё, что лежит в какой системе — знаете только вы. Каждый пишет свой раздел.

### 2. Проверьте, что контекст работает

> Расскажи, чем занимается наша компания и где у нас узкие места

Ответ по делу — контекст на месте.

### 3. Попробуйте задачу

> Разбери эту планёрку и вытащи задачи

> Собери акт по шаблону для контрагента X

> Проверь этот документ по методу светофор

## Что внутри

```
Контекст/Компания/   восемь разделов: о компании, площадки, ассортимент,
                     команда, закупки, производство, отгрузка, учётные системы
Проекты/             результаты работы
База знаний/         процессы, регламенты, справочники
Шаблоны/             КП, бриф, отчёт по встрече
Входящие/            файлы на обработку
.claude/commands/    12 команд
.claude/skills/      6 скиллов
```

### Скиллы

| Скилл | Что делает |
|---|---|
| `/обогатить-компанию` | собирает сведения о вашей компании и раскладывает по разделам |
| `/разбор-встречи` | расшифровка планёрки → саммари, решения, задачи |
| `/создать-документ` | .docx по вашему шаблону: акты, спецификации, отчёты |
| `/база-знаний` | документы → связанные заметки, которые модель находит сама |
| `/мини-стратсессия` | модель задаёт вам вопросы по контексту и показывает узкие места |
| `/управление-контекстом` | как не упереться в лимит в длинной сессии |

## Правило про данные

**Сюда — как у нас устроено. Не сюда — сколько это стоит.**

Себестоимость, цены, рецептуры, выгрузки, персональные данные и договоры в репозиторий не кладутся. Они живут рядом с папкой на вашей машине: модель их читает, наружу они не уходят.

Если контекст компании нужен всей команде и при этом не должен быть публичным — попросите вашу ИТ-службу завести приватный репозиторий. Это работа на один вечер, и после неё контекст остаётся компании, даже когда сотрудник уходит.

## Обмен внутри команды

Одно правило снимает почти все конфликты: **один раздел — один владелец.** Закупки описывает закупщик, производство — производственник, отгрузку — логист. Пересечений не возникает, потому что их нет по построению.
