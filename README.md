# AI Workspace — Стартовый набор

Рабочее пространство для работы с Claude Code. Забрал — настроил — работаешь.

Сделано для команд: контекст компании пишет не один человек, а каждый про своё направление.

---

## Как забрать себе

**Не нужен GitHub-аккаунт и не нужен git.** Создай на своём компьютере пустую папку, открой её через Claude Code и скажи:

> Сходи в репозиторий https://github.com/miheydev/ai-workspace-ru и скопируй его содержимое сюда.

Он всё принесёт. Тот же приём работает для любых знаний, которые ты найдёшь в сети — попроси принести и разложить.

Если git привычнее:

```bash
git clone https://github.com/miheydev/ai-workspace-ru.git
```

## Быстрый старт

### 1. Заполни контекст компании

```
/enrich-company
```

Спросит название, сайт, ИНН и бренды, дальше уйдёт собирать. Занимает 15–25 минут — запусти и займись другим. Вернётся с восемью заполненными разделами и честным списком того, чего не нашёл.

**Дальше руками.** Всё, что не восстанавливается снаружи — как устроены закупки, где теряется сырьё, что лежит в какой системе — знаете только вы. Каждый пишет свой раздел.

Если хочешь настроить пространство под себя вопрос-ответом, скажи Claude:

> Помоги настроить рабочее пространство под нас. Задавай вопросы — я буду отвечать голосом.

### 2. Проверь, что контекст работает

Спроси Claude:

> Расскажи, чем занимается наша компания и где у нас узкие места

Если ответ по делу — всё настроено.

### 3. Попробуй первую задачу

> Разбери эту планёрку и вытащи задачи

> Собери акт по шаблону для контрагента X

> Проверь этот документ по методу светофор

Claude найдёт подходящую команду и выполнит.

## Как добавить свою команду или скилл

**Команда** — простая: файл в `.claude/commands/`, например `моя-команда.md`. Опиши, что Claude должен делать: контекст, шаги, формат результата. Дальше просто скажи задачу — он найдёт и использует.

**Скилл** — папка в `.claude/skills/`, внутри файл `SKILL.md`. Отличается тем, что в нём есть описание, по которому Claude сам понимает, когда его применять, и явные правила — границы, за которые нельзя. Открой любой из семи существующих, там видно устройство.

Правило одно: **скилл — это не хитрый промпт, а ваша инструкция сотруднику, записанная один раз.**

## Советы

- **Говори голосом** — это в 3-5 раз быстрее печати
- **Чем больше контекста — тем лучше.** Загрузи документы о бизнесе в `Knowledge/`
- **Чем точнее опишешь нужный результат — тем лучше.** Это и структура запроса, и его половина
- **Результат в файл, не в чат.** Claude сам сохраняет результаты в `Projects/`
- **Кинь файл в `Inbox/`** и скажи «посмотри что во входящих» — Claude обработает
- **Новая тема = новая сессия.** Это помогает Claude сосредоточиться на одной задаче

## Где живёт этот репозиторий

Этот — публичный и учебный. Всё, что в него закоммичено, видно всем. Поэтому `.gitignore` по умолчанию не пускает в git выгрузки и таблицы: xlsx, csv, pdf, docx и всё содержимое `Inbox/`. Файлы при этом спокойно лежат в папке, Claude их читает — они просто не уезжают в историю репозитория.

**Когда репозиторий станет вашим, правила меняете вы.** Приватный на GitHub, свой git-сервис, репозиторий внутри организации — во всех этих случаях держать выгрузки и данные о клиентах рядом с контекстом нормально и часто удобно. Нужные строки из `.gitignore` убираются, и всё начинает версионироваться вместе.

Завести приватный репозиторий — работа на вечер для ИТ-службы. После неё контекст остаётся компании, даже когда сотрудник уходит.

Одно стоит держать в голове независимо от того, где лежит папка: `.gitignore` фильтрует по расширению файла и не видит цифру, вписанную текстом в `.md`.

## Обмен внутри команды

Одно правило снимает почти все конфликты: **один раздел — один владелец.** Закупки описывает закупщик, производство — производственник, отгрузку — логист. Пересечений не возникает, потому что их нет по построению.
