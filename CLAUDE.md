> Чтобы настроить под себя — скажи Claude: «Помоги настроить рабочее пространство под нас»

## Язык и стиль

- Общение: русский
- Стиль документов: деловой, но без канцелярита
- Обращение: на «ты»

## Как работаем

- Результаты — в файлы, не в чат (краткое резюме в чат, полный текст — в файл)
- Если результат нужен дольше одной сессии — он должен лежать файлом, а не в переписке
- Спрашивай перед удалением или перезаписью файлов
- Не создавай файлы «на будущее» — только то, что нужно сейчас
- Если задача большая — сначала покажи план, потом делай
- Перед изменением файла — сначала прочитай его

## Структура рабочего пространства

```
Context/
  Company/          — кто мы: восемь разделов по направлениям
  tone-of-voice.md  — как мы разговариваем с клиентами
Projects/           — результаты работы (КП, письма, анализы, посты)
Knowledge/          — документы о бизнесе (услуги, регламенты, кейсы)
Templates/          — шаблоны документов с плейсхолдерами
Inbox/              — файлы для обработки (кинул → попросил разобрать)
```

## Что можно и чего нельзя класть в этот репозиторий

**Можно:** описания процессов, инструкции, скиллы, сведения о компании словами.

**Нельзя:** себестоимость, цены закупки, рецептуры и технологические карты, выгрузки учётных систем, персональные данные сотрудников и клиентов, договоры, банковские реквизиты.

Правило простое: **сюда — как у нас устроено, не сюда — сколько это стоит.**

Выгрузки и документы лежат в этой же папке, в `Inbox/`. В git они не уходят: `.gitignore` не пускает xlsx, csv, pdf, docx и всё содержимое `Inbox/`. Это страховка от частой ошибки, а не гарантия — цифру, вписанную текстом в `.md`, она не остановит.

## Важные правила

- НЕ удаляй файлы без моего подтверждения
- НЕ выводи конфиденциальные данные в чат
- НЕ коммить `.env`, пароли, ключи и токены. Нашёл секрет в файле — скажи сразу
- Читай файл перед изменением — никогда не перезаписывай вслепую
- При создании документов — используй шаблоны из `Templates/`, если подходящий есть
- Используй контекст из `Context/Company/` для персонализации документов
- Если в задаче больше одного пункта — перед словом «готово» пройди по списку и отметь статус каждого

## Обмен внутри команды

**Один раздел — один владелец.** Закупки описывает закупщик, производство — производственник, отгрузку — логист. Пересечений не возникает, потому что их нет по построению.

Всё, что нужно только одному человеку, остаётся у него в папке. В общий репозиторий уходит то, что нужно команде: скиллы, инструкции, контекст компании.

## Чем пользоваться

Скажи задачу словами — Claude сам подберёт подходящее. Список неполный, остальное — в `.claude/commands/` и `.claude/skills/`, файлы читаемые.

| Что нужно | Команда |
|---|---|
| Заполнить контекст компании | `/enrich-company` |
| Разобрать планёрку | `/meeting-review` |
| Собрать документ по шаблону | `/create-document` |
| Разложить документ в базу знаний | `/knowledge-base` |
| Разобрать компанию вопросами | `/strategy-session` |
| Настроить пространство под себя | `/setup` |
