# Рабочее пространство компании

> Главная инструкция. Claude Code читает её первой при каждом запуске — до любого ответа.
> Пространство пустое? Скажи: «помоги настроить рабочее пространство под нас».

**Как разговариваем с клиентами** → [Context/tone-of-voice.md](Context/tone-of-voice.md)

## Критические правила (ОБЯЗАТЕЛЬНО)

### 1. Читай файл перед изменением

**НИКОГДА** не перезаписывай файл, не прочитав его.
- Сначала прочитать → понять, что там → потом менять
- Исключение: создание нового файла
- **Почему:** в файле могут быть чужие правки, которых нет в твоей истории. Перезапись вслепую стирает работу коллеги молча

### 2. Результат — в файл, а не в чат

**Если результат нужен дольше одной сессии — он должен лежать файлом.**

Создавай **без вопросов:**
- Документ клиенту → файл в `Projects/`
- Разбор встречи → саммари + обновление контекста
- Анализ, исследование → результат в `Knowledge/`
- README для навигации в новой папке

**НЕ создавай:**
- Файлы «на будущее», обёртки и абстракции про запас
- Документацию к тому, что не менялось
- Дубли уже существующих файлов

**Почему:** чат обнуляется, файл остаётся. Разбор на два экрана, оставленный в переписке, придётся делать заново.

### 3. Безопасность

- **НЕ** коммить `.env`, пароли, ключи, токены
- **НЕ** выводить содержимое конфиденциальных файлов в чат — путь к файлу вместо содержимого
- Нашёл секрет внутри файла — **сказать сразу**, не молча
- Перед коммитом проверить `.gitignore`
- **Почему:** то, что попало в git, остаётся в истории даже после удаления файла

### 4. Не выдумывай факты о компании

**Цифры, сроки, имена, названия клиентов — только из `Context/`, `Knowledge/` или от человека.**
- Нет источника — пропусти утверждение и скажи, чего не хватает
- Пропуск лучше правдоподобной выдумки: выдумку заметит клиент, а не ты
- **Почему:** документ уходит наружу под именем компании. Одна выдуманная цифра стоит дороже, чем десять пустых мест

### 5. Тексты без канцелярита

- Стиль — как в [Context/tone-of-voice.md](Context/tone-of-voice.md), если он заполнен
- **НЕ** использовать: «стоит отметить», «в современных реалиях», «не просто X, а Y», риторические вопросы с ответом на них же
- Живая речь заказчика — не мусор. Не вычищай её до гладкости
- **Почему:** текст, написанный «как у всех», читается как написанный не нами

### 6. Самопроверка перед словом «готово»

**Если в задаче больше одного пункта** — перед ответом пройди по списку и отметь статус каждого: сделано / пропущено / непонятно. Пропущенное доделать. Только потом писать итог.
- **Почему:** без списка легко закрыть три пункта из пяти и сказать «готово». Ловить это приходится человеку

### 7. Спрашивай перед необратимым

- **НЕ** удалять файлы без подтверждения
- **НЕ** перезаписывать чужие правки
- Большая задача — сначала показать план, потом делать
- **Почему:** переспросить стоит десять секунд, восстановить — полдня

## Где живёт этот репозиторий

Сейчас он публичный и учебный: всё, что закоммичено, видно всем. Поэтому по умолчанию `.gitignore` не пускает в git выгрузки и таблицы — xlsx, csv, pdf, docx и содержимое `Inbox/`. Сами файлы при этом лежат в папке и читаются как обычно, просто не уезжают в историю.

Когда репозиторий станет нашим — приватным на GitHub, на своём сервере или внутри организации — эти правила меняем мы. Что держать рядом с контекстом, а что отдельно, решает владелец репозитория.

**Claude: если не знаешь, кто видит этот репозиторий, — спроси, прежде чем класть в него что-то чувствительное.**

## Обмен внутри команды

**Один раздел — один владелец.** Закупки описывает закупщик, производство — производственник, отгрузку — логист. Пересечений не возникает, потому что их нет по построению.

Скажи задачу словами — Claude подберёт сам. Список неполный, остальное — в [.claude/commands/](.claude/commands/) и [.claude/skills/](.claude/skills/), файлы читаемые.

| Что нужно | Команда |

| Найти узкие места вопросами | `/strategy-session` |
| Настроить пространство под себя | `/setup` |

## Как добавить свою команду

1. Создать папку в `.claude/skills/` — например `моя-задача/`
2. Внутри — файл `SKILL.md`: что делать, откуда брать контекст, в каком виде результат
3. Перезапустить Claude Code — команда `/моя-задача` появится в списке

**Папка обязательна.** Просто файл `.claude/skills/моя-задача.md` командой не станет — Claude Code ищет `SKILL.md` внутри папки.
